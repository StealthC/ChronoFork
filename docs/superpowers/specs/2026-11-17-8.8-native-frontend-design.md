# Phase 8.8 Design — Native windowed frontend

**Date:** 2026-11-17
**Phase:** `8.8`
**Surface:** `UI`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-17
**Builds on:** Phase 8.7 — `chronofork-runtime::{ExecutionMode, Target, run_to_target, Pacer, HostClock, CaptureSink}`; Phase 8.3 — `backend_api::media::{MediaSource, VideoFrame}`; Phase 8.4 — `AudioChunk`; Phase 8.5 — controller input words.

## Goal

Ship an optional native window that presents Mega Drive video and audio, accepts keyboard
input mapped to the controller, paces at 60/50 fps, and offers pause/step/save/load — in a
separate crate behind an accepted ADR that supersedes ADR-0013's no-toolkit constraint, while
the headless path keeps working unchanged.

## Approach

**ADR-0015 and the boundary.** A new accepted **ADR-0015** records the native frontend
decision: `winit` + `softbuffer` + `cpal` in a new `chronofork-frontend` crate; the crate
depends only on `chronofork-core`, `chronofork-backend-api` and `chronofork-runtime`; the CLI
composes it with a concrete backend and injects a `Box<dyn Backend>`. `chronofork-gui` stays
presentation-only and dependency-free; the core crates and `chronofork-megadrive` gain no
toolkit/audio dependency. Licenses are checked (winit/softbuffer/cpal are MIT/Apache-2.0
compatible) and recorded in `THIRD_PARTY_NOTICES.md`; the workspace's `unsafe_code = "forbid"`
still applies to first-party code, and dependency `unsafe` is accepted risk documented in the
ADR. Headless builds compile without a display; only `run_window` needs one.

**Structure.** `frontend/src/lib.rs` (config, run loop), `window.rs` (winit event loop and
softbuffer surface), `video.rs` (RGBA `VideoFrame` → softbuffer buffer, scaling), `audio.rs`
(cpal output stream, bounded ring buffer, silence on underrun), `input.rs` (keyboard →
documented controller word) and `controls.rs` (pause, step, save-state, load-state). The run
loop uses `chronofork-runtime`'s `Pacer` and `ExecutionMode::Paced` with the real host clock,
and `Manual` for single-steps. It never owns canonical state: save/load go through
`Backend::snapshot`/`restore`, and the frame/audio data comes from `MediaSource`.

**Behaviour.** Default 60 fps NTSC / 50 fps PAL from the descriptor's video standard; a
`--scale` factor with integer nearest-neighbour scaling; video-only or audio-only modes when a
device is missing (`NoAudioDevice` degrades to silent video with a reported status, not a
crash); pause freezes stepping; step advances exactly one frame; save writes a versioned
snapshot through the backend API; load rejects incompatible snapshots with the typed error and
leaves the machine untouched. Keyboard mapping: arrows = D-pad, `Z/A` = B/A, `X/S` = C/Start,
`D/F/C` = X/Y/Z, `Enter` = Mode, `Space` = pause, `.` = step, `F5`/`F8` = save/load, `Esc` = quit.
The mapping is documented and unit-tested; no gamepad API is added (it would be a new
dependency and is not required by the DoD).

**Honesty and evidence.** The frontend is optional: the headless CLI and all existing tests do
not require a window or an audio device. `Capabilities.rendering/audio` are already true from
8.3/8.4; the frontend reports `NoDisplay`/`NoAudioDevice` rather than fabricating output. Tests
cover everything deterministic (mapping, scaling, pacing math with a fake clock, save/load
round-trip, headless typed error); the actual window/audio smoke test is a documented manual
step because CI has no display. Performance pacing is presentation policy and never changes
canonical hashes (ADR-0014).

## Tests

- Unit: keyboard→controller mapping (every documented key), scaling algorithm, ring-buffer
  underrun → silence, pause/step state machine, save/load round-trip through a fake backend,
  snapshot rejection leaves state untouched, `NoDisplay` typed error path, capability gate.
- Integration: the frontend run loop with a fake presenter and `ManualClock` consumes exactly
  the requested number of frames and does not sleep in manual mode; a paced run with a fake
  clock does not change frame hashes compared to unpaced.
- CLI: `chronofork window` without a display exits with the documented typed error and does not
  panic; `--help` lists the command.
- Manual (documented, not CI): open a window on a machine with a display, confirm video and
  audio, keyboard input, pause/step and save/load; record the result in the evidence page.
- Regression: full gate; no toolkit dependency leaks into core/`chronofork-gui`; headless
  `megadrive run` unchanged.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| CI lacks ALSA/X11/Wayland system libraries | Build fails | Install the packages in CI; keep the crate a normal workspace member; document local prerequisites |
| Audio device absent/underrun | Crashes or hangs | Bounded ring buffer, silence on underrun, `NoAudioDevice` degradation |
| Pacing leaks host time | Non-determinism | Reuse ADR-0014 runtime; equality test with a fake clock |
| Toolkit dependency breaks the boundary | Architecture violation | ADR fixes allowed deps; a boundary test parses the crate's `Cargo.toml`; `chronofork-gui` untouched |
| Window smoke test cannot run in CI | Unverified UI | Deterministic unit/integration coverage + documented manual smoke evidence |
