# Phase 8.2 Design — Complete 68000 and the cycle time model

**Date:** 2026-11-17
**Phase:** `8.2`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-17
**Builds on:** Phase 8.1 — `cartridge::Cartridge` (`read8`/`read16`/`read32`/`snapshot_bytes`), `cartridge::Tmss`, `cartridge::Region::is_pal`, `MegadriveConfig { video, tmss }`, `MegadriveFactory::with_config`, `MegadriveBus::new(Cartridge)`, payload v3 layout.

## Goal

Implement the whole documented MC68000 instruction set, addressing modes, privilege and
exception groups with per-instruction cycle accounting, and replace the instruction-quantum
clock with canonical emulated master cycles — the time base every later M8 phase builds on.

## Approach

**Canonical time is master cycles.** The backend's `Tick` becomes one master-clock cycle
(`chronofork_core::tick` already documents that a tick may be a master-clock cycle). One 68000
cycle is 7 master cycles; NTSC has 3420 master cycles per scanline and 262 lines per frame,
PAL 3420 and 313 (59.92 Hz / 49.70 Hz). The 68000 execution result carries its 68000-cycle cost,
and the backend advances the master counter by `cycles * 7`. Z80 (8.4) and VDP (8.3) step from
integer accumulators with carried remainders, so no floating point and no host clock enters
canonical state. *Alternatives rejected:* 68000 cycles as the canonical unit (the Z80's
master/15 ratio is not integral), and a fully microcycle-accurate bus model (8.3 adds the VDP
and DMA contention it needs; doing both at once would double the phase).

**CPU structure.** `cpu.rs` (1877 lines today) becomes a module tree: `cpu/mod.rs` (register
file, reset, step, exceptions), `cpu/decode.rs` (opcode classification), `cpu/ea.rs`
(effective-address decode/read/write and extension words), `cpu/exec/mod.rs` plus
`cpu/exec/{move,arith,logic,shift,bit,control,system,bcd}.rs`, and `cpu/timing.rs`. This is a
restructure of an existing load-bearing file, so the decode table is data-driven and the
execution groups are pure functions over the register file and bus. The implementer keeps the
public `M68000` surface (`new`, `reset`, `step`, `interrupt`, `sr`, `registers`) and adds
`usp`, `ssp`, `set_sr`, `cycles`.

**Instruction set and privilege.** All documented data movement (MOVE/MOVEA/MOVEQ/MOVEM/MOVEP/
LEA/PEA/CLR/TST/EXT/SWAP), arithmetic (ADD/ADDA/ADDQ/ADDI/SUB/SUBA/SUBQ/SUBI/CMP/CMPA/CMPI/
CMPM/NEG/NEGX), logic (AND/OR/EOR/ANDI/ORI/EORI/NOT), shifts and rotates (ASL/ASR/LSL/LSR/ROL/
ROR/ROXL/ROXR in register and memory forms), multiply/divide (MULU/MULS/DIVU/DIVS), BCD (ABCD/
SBCD/NBCD), bit operations (BTST/BSET/BCLR/BCHG), control flow (BRA/BSR/Bcc/DBcc/Scc/JMP/JSR/
RTS), and system (MOVE to/from SR, MOVE to/from USP, ORI/ANDI/EORI to CCR and SR, STOP, RESET,
RTR, TRAP, TRAPV, CHK, ILLEGAL) are implemented. User and supervisor stacks are separate;
`MOVE to SR`, `STOP`, `RESET`, `RTE` and `MOVE to USP` are privileged and raise a privilege
violation in user mode. `M68000::interrupt` keeps its six-byte frame contract.

**Exceptions.** Exception groups 2–7 are delivered through the vector table: address error
(group 3, including odd-address and bus-window faults surfaced by the bus), illegal instruction
and privilege violation (group 4), trace, `DIVU`/`DIVS` zero divide, `CHK`, `TRAPV` (group 5),
interrupt (group 6) and `TRAP` (group 7). Guest faults that the current slice returns as host
`CpuError`s become guest exceptions instead; `CpuError` remains only for host-level failures
(overflow of the emulated counter, a broken snapshot, a trace-capacity error). The 68000
prefetch queue is **not** cycle-modelled: the functional model fetches the next word on demand
and the cost table accounts for the documented bus cycles. That limitation is recorded and
phase 8.6 may supersede it only with an ADR and new evidence.

**Timing.** `cpu/timing.rs` holds the documented base and effective-address cycle table, keyed
by the decode's instruction class and EA kind (byte/word/long where the 68000 distinguishes
them). `M68000::step` returns `InstructionOutcome { cycles: u16 }` (68000 cycles). Tests pin a
sample of documented values (`NOP` 4, `MOVE.B Dn,Dm` 4, `MOVE.W (An),Dn` 8, `MOVE.L #imm,Dn` 12,
`ADD.W Dn,Dm` 4, `MULU` 70, `DIVU` 140, exception entry 34) and the differential harness
compares every executed instruction's cycle total against the oracle. The oracle currently
ignores its `cycle` column; the harness extension compares per-instruction deltas, which is the
documented timing evidence for this phase.

**Video timeline.** `interrupts.rs`'s quantum scheduler becomes a cycle timeline: HBlank is
requested when a line's 3420 master cycles complete, VBlank when the active-line count
(224 NTSC / 240 PAL) is reached, and pending/coalescing/acknowledge semantics stay as they are.
`SchedulerConfig` loses `instructions_per_line` and gains the fixed video timeline; the CLI's
`--instructions-per-line` flag is removed and its help text updated. The masked-request
retention, level-7-always rule, VBlank-before-HBlank order and delivered-level IPM behaviour
are preserved and re-tested.

**State and configuration.** Payload magic becomes `CFMD68K4`, payload version 4, state hash
magic `CFMDSTATE4`, configuration magic `CFMDCONF4`. Capture: CPU reset state (including USP,
SSP, SR, PC, halted), master-cycle counter, RAM, VDP snapshot, cycle timeline, cartridge state
from 8.1. v1–v3 payloads are rejected with typed errors. The state hash includes the master
counter, so timing is part of identity.

**Superseded contracts.** M3's hardware acceptance rows that assert the instruction quantum and
M1–M5 trace/tick projections change meaning: tick is now a master cycle, so existing `.cfmovie`,
trace and state fixtures are re-evidenced or explicitly marked superseded in their owning docs.
The synthetic `demo` must remain byte-identical; the Mega Drive demo's hash lines are re-pinned
with the documented version bump. `Capabilities::rendering` and `::audio` stay false.

## Files / Modules Touched

- `crates/chronofork-megadrive/src/cpu.rs` → `cpu/` module tree (state, decode, EA, exec, timing).
- `crates/chronofork-megadrive/src/interrupts.rs` — cycle timeline, no instruction quantum.
- `crates/chronofork-megadrive/src/backend.rs` — master-cycle advance, exception routing,
  payload v4, hashes, `InstructionOutcome`.
- `crates/chronofork-megadrive/src/bus.rs` — typed bus-fault variants used by address-error
  exception delivery; no new windows.
- `crates/chronofork-megadrive/src/disasm.rs` — complete 68000 decoding table (the disassembler
  may keep its subset, but the decoder must be the single table).
- `crates/chronofork-megadrive/src/inspect.rs` — add `usp`, `ssp`, `master_cycles`, `cycles`.
- `crates/chronofork-megadrive/tests/{cpu_full,exceptions,timing}.rs` — new.
- `crates/chronofork-cli/src/main.rs` — remove `--instructions-per-line`, report cycles.
- `scripts/oracle-diff.py` — per-instruction cycle comparison; new synthetic corpus.
- `docs/architecture/{megadrive-slice,execution-model}.md`, `docs/quality/m3-hardware-acceptance.md`,
  `docs/requirements/functional.md` — capability and supersession text after the phase closes.

## Tests

- Unit: every instruction form and EA, flag matrices (`N/Z/V/C/X`), privilege violations,
  exception vector/frame correctness, cycle-table samples, shift-count masking, divide overflow
  and zero-divide vectors, BCD behaviours, `MOVEM` register-mask order, `DBcc`/`Scc` outcomes.
- Property: decode never panics and never executes an opcode it does not classify; a round-trip
  snapshot restores every CPU field.
- Integration: cycle timeline produces the documented line positions for NTSC and PAL; masked
  interrupt retention and delivery order survive the rewrite; the synthetic boot ROM in 8.1 still
  reaches its marker with cycle timing; 68000 exceptions reach handlers written by a synthetic
  ROM (illegal, privilege, zero divide, TRAP, interrupt).
- Differential: extended `scripts/oracle-diff.py` compares instruction addresses, per-instruction
  cycle deltas and final registers over the existing three ROMs plus at least five new synthetic
  ROMs covering EAs, shifts, BCD, MOVEM/MOVEP, exceptions and multiply/divide. The evidence page
  records the pinned oracle revision and the controlled conditions.
- Regression: full workspace gate; synthetic `demo` byte-identical; `megadrive demo`
  deterministic; trace/state CLI outputs re-pinned for the documented tick semantics.

## Open Questions

None. The cycle base (master cycles), the functional-prefetch limitation and the v4 state break
were decided in the phase design review on 2026-11-17.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Full ISA is very large | Phase overruns or partial delivery | Module split plus 16 tasks; each group lands with its own tests; no phase closes until the decode table admits no undocumented opcode silently |
| Cycle table errors diverge from the oracle | Timing claims fail | Per-instruction differential comparison; pinned timing samples; document exceptions |
| Tick semantics change invalidates movies/traces/fixtures | Broken M2/M3 evidence | Version bumps, reject-only, explicit supersession notes and re-recorded fixture evidence |
| Exception routing changes existing error paths | Regressions across layers | Keep host errors for host failures; guest faults tested through handlers; full workspace gate |
