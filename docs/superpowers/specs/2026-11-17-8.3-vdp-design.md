# Phase 8.3 Design — Complete VDP

**Date:** 2026-11-17
**Phase:** `8.3`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-17
**Builds on:** Phase 8.1 — `cartridge::Cartridge` and `MegadriveBus::new(Cartridge)`; Phase 8.2 — `cycles::{MASTER_CYCLES_PER_LINE, active_lines, lines_per_frame}`, `M68000::step -> InstructionOutcome { cycles }`, `InterruptScheduler::advance_master`, `MegadriveBackend::master_cycles`, payload v4.

## Goal

Turn the VDP port window into a complete video processor: CRAM/VSRAM, 256/320 rendering with
planes, window, sprites, scrolling, priority and shadow/highlight, DMA, FIFO/access timing,
H/V counters and VBlank/HBlank interrupt enable/acknowledge — with a deterministic frame
output that phases 8.7 and 8.8 capture and present.

## Approach

**Module split.** `vdp.rs` (1101 lines today) becomes `vdp/mod.rs` (device, ports, snapshot),
`vdp/regs.rs` (register semantics and address decoding), `vdp/timing.rs` (line/dot position,
status latches, H/V counters), `vdp/render.rs` (planes, window, sprites, priority, shadow),
`vdp/dma.rs` (transfer engine) and `vdp/fifo.rs` (write queue and access slots). The existing
port surface (`read8/write8/read16/write16`, register auto-increment, HV counter port) and its
typed errors are preserved; the snapshot moves to `CFVDP002` v2 with CRAM, VSRAM, FIFO, DMA,
frame counter, status latches and H/V position.

**Memory model.** VRAM stays the slice's linear 64 KiB big-endian byte array (the real
byte-swapped/interleaved layout is not modelled and stays a documented limit). CRAM is 64
words of 9-bit color (two words per entry, 128 bytes); VSRAM is 40 words of 11 bits; the
sprite attribute table lives at the register-selected VRAM offset (80 entries × 8 bytes).
Data-port byte accesses combine into a 16-bit word (byte writes duplicate into both halves,
byte reads select a lane) — the existing behaviour is kept and tested.

**Rendering.** Rendering is per scanline into a `FrameBuffer { width: u16 (256 or 320),
height: u16 (224 NTSC / 240 PAL), indices: Vec<u8> }`; colour lookup happens once when a frame
is converted to RGB. Each line composes: plane A and plane B nametables with horizontal and
vertical scrolling (`0x0B`/`0x0D` full, column and line modes; the undocumented modes 2/3 are
documented as falling back to full-screen scroll), the window plane (`0x11`/`0x12`), and 80
sprites in link order with size/priority, duplication rules, collision and overflow status
bits. Priority follows the documented table (sprite > plane A > plane B); shadow/highlight is
applied when `0x0C` bit 3 is set, using the documented operator/highlight priority rules.
Border colour fills the leftmost 8/rightmost 8 pixels in H40 and the whole overscan area.
Interlace is **not** implemented in this phase; it is recorded as a residual limit because
neither fixture enables it and it changes row timing.

**Timing and FIFO.** The VDP is driven by the master-cycle timeline from 8.2: each line yields
3420 master cycles divided into access slots. CPU port writes enter a 4-word FIFO; when the
FIFO is full the write adds deterministic wait cycles to the instruction's cost. DMA consumes
the documented slots (68k→VRAM/CRAM/VSRAM, VRAM fill, VRAM copy), sets `DMA_BUSY`, and steals
the CPU slots the real chip steals. Status bits now come from device state instead of
constants: PAL, DMA busy, HBlank, VBlank, odd frame, sprite collision, sprite overflow, VINT
pending, FIFO empty/full. The H counter is computed from the line position using the
documented per-line table approximation, the V counter from the line number with the video
standard's offset; both are pinned by tests and explicitly not claimed to be dot-exact.

**Interrupts.** VBlank and HBlank enable come from register `0x00` bits 5 and 4; pending and
acknowledge are VDP-owned. A status read reports the pending state and never acknowledges,
clears or consumes a VBlank/HBlank request: only the 68000 taking the interrupt acknowledges
the delivered source. This deliberately preserves the merged 8.2 no-acknowledge contract
(the canonical slice page and `vdp_interrupts`/backend tests pin it); the earlier 8.3 draft's
"clear on status read" wording is superseded. VINT is asserted while a VBlank is pending and
enabled. The backend keeps the 68000 delivery rule and `RTE` semantics from 8.2. H/V counter (line
interrupt) is **not** enabled by this phase; timer/controller interrupt sources land in 8.5.

**Media seam.** `backend-api` gains a small `media` module: `VideoFrame { width, height, rgba:
Vec<u8> }`, `AudioChunk { samples: Vec<i16>, sample_rate_hz: u32, channels: u8 }`, and
`MediaSource { fn take_video_frame(&mut self) -> Option<VideoFrame>; fn take_audio_chunk(&mut
self) -> Option<AudioChunk>; }`. `Backend` gains `fn media_mut(&mut self) -> Option<&mut dyn
MediaSource> { None }`; the Mega Drive backend implements it, the test backend keeps the
default. This keeps transport, service and GUI unaware of the backend while giving 8.7 a
stable capture path. The GUI's presentation types stay untouched.

**Capability and evidence.** `Capabilities::rendering` becomes `true` only when the phase's
frame tests pass; the canonical slice page lists the modes and limitations. Evidence is
(a) VDP device-state equality against the pinned Exodus oracle at synchronized instruction
boundaries — registers, VRAM, CRAM, VSRAM, status and counters, since the headless oracle has
no framebuffer — and (b) exact frame hashes for synthetic programs pinning the renderer's
output across runs and across the execution modes 8.7 adds. Cross-emulator pixel comparison
is not claimed.

**State.** Backend payload becomes `CFMD68K5` v5, state hash `CFMDSTATE5`, config hash
`CFMDCONF5`, including the VDP snapshot and frame counter; v1–v4 payloads are rejected.

## Tests

- Unit: register decode and masking, CRAM/VSRAM write semantics, auto-increment wrap, HV counter
  values per line, FIFO occupancy and stall accounting, DMA mode decoding and slot costs,
  nametable address masking, scroll modes, sprite link/size/priority/collision/overflow, shadow
  and highlight priority, border/overscan.
- Frame: deterministic synthetic scenes (solid plane, scrolled plane, window, sprite stack,
  shadow/highlight) pinned by SHA-256; a frame rendered by stepping must equal the frame
  rendered by running the whole line (no hidden state), and a second identical run must be
  byte-identical.
- Integration: DMA transfer followed by CPU reads sees the transferred bytes; FIFO full stalls
  the CPU by the documented cycles; VBlank enable/ack controls 68000 interrupt delivery; the
  synthetic cartridge of 8.1 renders a frame without touching the mapper.
- Differential: VDP state comparison against the oracle over synthetic programs; the harness
  reports the first mismatch with register/VRAM address context. Fixture-dependent and skippable
  with a reason; never silently passes on a missing oracle.
- Regression: full gate; synthetic `demo` byte-identical; `megadrive demo` deterministic;
  v1–v4 snapshots rejected.

## Open Questions

None. The headless oracle's lack of a framebuffer and the "device-state + exact frame hashes"
evidence model were decided with the owner on 2026-11-17.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Renderer correctness is hard to isolate | Frames look plausible but are wrong | Synthetic scenes with known expected pixels; oracle VDP state checks; priority table tests |
| FIFO/DMA timing model changes instruction costs | Determinism or oracle divergence | Wait cycles are explicit integer additions; cross-mode equality tests from 8.7; documented approximation |
| H counter table is approximate | Timing-sensitive games differ | Document the approximation, pin per-line values, defer dot-exact evidence to H5 |
| New `MediaSource` trait ripples through layers | API churn | Default `None` method; only the Mega Drive backend implements it; service/GUI untouched |
| Payload v5 break invalidates fixtures | Lost reproducibility | Reject-only versioning, re-recorded evidence, supersession notes |
