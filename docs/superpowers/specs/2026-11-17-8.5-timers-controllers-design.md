# Phase 8.5 Design — Timers, controllers and interrupts

**Date:** 2026-11-17
**Phase:** `8.5`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-17
**Builds on:** Phase 8.2 — `cycles`, `InterruptScheduler` cycle timeline, manifest mask rule, payload v4; Phase 8.3 — `vdp::{Vdp, timing, interrupts}`, `VdpInterrupts`, payload v5; Phase 8.4 — `z80::{Z80, interrupts}`, `audio::ym2612::{Ym2612, YmIrq}`, timer status flags, payload v6.

## Goal

Wire the remaining interrupt sources — YM2612 Timers A/B to the Z80 and the VDP H-int counter to
the 68000 — and implement the full TH-latched 3-button and 6-button controller protocol on
ports 1–2, integrated with the cycle timeline.

## Approach

**Interrupt aggregation.** The backend becomes the single delivery point: VDP VBlank (level 6) and
HBlank (level 4) remain 68000 sources; the VDP H-int counter adds level 4 requests at its
programmed line offset; the YM2612 Timer A/B overflows request the Z80 IRQ line (delivered by the
Z80's `IM` mode) instead of the 68000. Levels 2/3/5, the Z80 NMI source and the VDP H/V-counter
interrupt are **not** wired and are recorded as residual limits. 68000 delivery keeps the 8.2 rule
(level 7 always, others strictly above the mask), one exception per instruction boundary, and the
`RTE` restore contract.

**VDP H-int.** Register `0x0A` is a line counter reloaded each line; when it reaches zero and HInt
is enabled (register `0x00` bit 4), the VDP requests level 4 at that line position and reloads. The
phase reuses the 8.3 timing state and adds the counter and its reload to the VDP snapshot.

**YM2612 timers.** Timer A counts `(1024 - NA) × 18` YM samples and Timer B `(256 - NB) × 288`,
where NA/NB come from registers `0x24–0x27`; the status flags are already implemented in 8.4. The
phase adds the countdown, overflow, reload and the enable/mask/reset bits, and asserts the Z80 IRQ
when an enabled timer overflows. The Z80 accepts it at an instruction boundary under `IFF1` (and
the `EI` delay), using its current `IM`.

**Controllers.** A `controller.rs` state machine per port models the TH latch: a byte write to the
port's control register toggles TH (low/high) and the next data read returns the phase-appropriate
active-low bits. Ports 1–2 implement 3-button (Up/Down/Left/Right/B/C) and 6-button (A/Start,
X/Y/Z/Mode) phases with the documented detection sequence: repeated TH high→low pulses under the
`~1.5 ms` timeout extend the phase count; the timeout is measured in master cycles and resets the
port to 3-button. Writes to the control registers (`0xA10008–0xA1000F`) and the version register are
modeled; port 3, analog and keyboard hardware stay residual limits per the owner decision. The
per-port `u32` `InputFrame` word gets a documented, stable bit layout in a `buttons` module (bits
0–11), so no movie-format change is needed and existing frames stay valid.

**State.** Payload `CFMD68K7` v7, `CFMDSTATE7`, `CFMDCONF7`: adds the H-int counter, YM timer
countdowns, controller latch state/counters and the arbitration snapshot already present. v1–v6
rejected. `Capabilities` is unchanged; interrupt and controller coverage is documented in the
capability page.

## Tests

- Unit: 3-button TH phases and active-low bits, 6-button sequence (3 reads then A/Start, then
  X/Y/Z/Mode), timeout reset at the documented master-cycle boundary, TH writes from both ports,
  Timer A/B periods/reloads/status flags, enable/mask bits, H-int counter reload and request,
  controller writes rejected for port 3.
- Integration: a synthetic program reads a 6-button sequence and stores the result in RAM; a YM
  timer overflow delivers a Z80 IRQ handled by a synthetic handler; HInt and VBlank are both
  deliverable and their mask interactions follow the documented order; the 8.1 boot cartridge and
  8.3 frame path still pass.
- Regression: full gate; synthetic `demo` byte-identical; `megadrive demo` deterministic; v1–v6
  snapshots rejected.

## Open Questions

None. Port 3/analog/keyboard are residual limits and interrupt levels 2/3/5 stay out of scope, as
decided with the owner on 2026-11-17.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Controller timing is sensitive | Games misread input | Master-cycle timeout with pinned boundary tests; protocol sequence tests |
| Timer formulas differ from hardware | Sound driver drift | Formula tests with documented values; oracle state comparison where available |
| Interrupt aggregation reorders delivery | Determinism/handler bugs | Single backend delivery point, mask-rule tests, one exception per boundary |
| Payload v7 break | Fixture invalidation | Reject-only versioning and supersession notes |
