# Phase 8.6 Design — Commercial compatibility, accuracy evidence and performance

**Date:** 2026-11-17
**Phase:** `8.6`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-17
**Builds on:** Phase 8.1 — `Cartridge`/TMSS/region and the fixture manifest; Phase 8.2 — cycle model and oracle cycle differential; Phase 8.3 — `VideoFrame` and VDP state differential; Phase 8.4 — `AudioChunk`, Z80/YM/PSG; Phase 8.5 — controller protocol and interrupts; payload v7.

## Goal

Drive the curated commercial fixtures — *Kid Chameleon* and *Chakan* — through boot, no-input
intro and TAS scenarios with deterministic frame/audio/state hashes, record an honest
compatibility matrix and H5 accuracy evidence, and reach measured interactive speed with
documented optimizations that do not change behavior.

## Approach

**Evidence harness, not a new emulator.** A `compat` module in the CLI drives the existing
backend through three scenarios per fixture and writes a machine-readable report
(`<out>/compat.json`) plus a human report (`<out>/compat.md`), with artifacts under the ignored
`docs`-adjacent `.research/` tree. Scenario results are executed evidence: a fixture-absent run
skips with `skipped: fixture-absent` and never passes silently. The tracked matrix
`docs/quality/m8-compatibility.md` records per-title, per-scenario status
(`boot`/`intro`/`play`/`input`/`audio`/`video`), the exact commit and evidence directory, and
known defects. No ROM bytes, frames, audio or save files are committed; only hashes and
non-redistributable evidence live under ignored paths, per the fixture manifest policy.

**Scenarios.** *Boot*: TMSS enabled, run to the first 120 frames, require no host error, at least
one frame and one audio chunk, and a controller-response probe (injecting a button changes work
RAM through the game's own input handling, proving the main loop is reached). *Intro*: no input
for a fixed frame count, capture one deterministic PNG-equivalent frame hash per second and an
audio hash; the two titles' GEMS intros exercise VDP/DMA/YM/PSG. *TAS*: record a short input
movie on the real backend, replay it with `tas verify`, and assert convergence and completion;
the movie is an ignored local artifact. "Playable" in the matrix means the scenario's executed
checks pass, never a universal claim.

**Accuracy evidence.** The oracle harnesses from 8.2–8.5 run over longer windows of the synthetic
corpus and, where the oracle exposes it, over fixture-derived state sequences: instruction
traces, cycle deltas, VDP and audio device state. A new `docs/research/m8-accuracy-evidence.md`
(H5 home) consolidates commands, pinned revisions, compared fields, pass/fail and explicitly
uncompared areas (pixel output, PCM samples, inputs not exercised). Divergences are recorded as
defects in the matrix, never explained away.

**Performance.** `chronofork megadrive bench --rom <fixture> --frames <N>` measures unpaced
throughput (frames/audio per wall-clock second) as a **host metric explicitly excluded from
canonical state**, and a release-mode run records the interactive rate. The workspace release
profile gains LTO and tuned codegen. Optimizations are limited to behavior-preserving ones:
decoded-instruction/opcode classification cache, allocation-free hot paths (no per-step `Vec`),
batched audio sample generation and per-scanline rendering reuse. Skip-frames, run-ahead and
dynamic recompilation remain out of scope. Every optimization lands only with the full
differential and determinism suite green; the bench numbers are re-recorded before/after.

**Compatibility fixes.** The phase is allowed to fix backend defects the fixtures expose
(documented in the matrix and evidenced by the scenario), but it does not add new device
features beyond 8.1–8.5; a missing feature found here becomes a recorded residual or a new
phase, not an unreviewed scope expansion. No payload change: state stays v7, and the phase's
output is evidence, performance and documentation.

## Tests

- Harness: missing fixtures skip with a reason and exit 0; a present fixture produces a report whose
  hashes are stable across two runs; the report contains no host path, token or wall-clock value.
- Scenarios: boot reaches the controller-response probe on both fixtures or records the exact failing
  check; intro produces frame/audio hashes; TAS records/verifies a short movie deterministically.
- Performance: bench reports a number and a frame count; the number is labelled non-canonical; a
  second run's report is not asserted equal (wall time varies) but the state hashes are.
- Regression: after every optimization, `./scripts/check.sh` and both demos stay green; the
  synthetic `demo` stays byte-identical.
- Differential: oracle full-window runs recorded with pass/fail and defects; no silent pass on a
  missing oracle.

## Open Questions

None. The curated set stays the two recorded fixtures (NTSC-U/Europe), PAL/JP play remains a
residual, and "playable" is defined by the executed scenario checks, as decided with the owner on
2026-11-17.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Real games expose many gaps | Phase balloons | Fix only evidenced defects; record residuals; no new features; escalate scope to a new phase |
| Fixture evidence is non-redistributable | Claims unverifiable by others | Hashes + matrix tracked, raw artifacts ignored; claims scoped to executed local runs |
| Optimizations change behavior | Silent divergence | Each optimization gated by differential + determinism tests; before/after bench hashes |
| Performance target missed | DoD fails | Profile first, optimize hot paths only, report the honest measured number and residual gap |
| TMSS/region mismatches | Fixtures fail to boot | TMSS enabled explicitly here; per-title region override; fixtures are JUE/U |
