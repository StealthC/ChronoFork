# Phase 8.4 Design — Z80, bus arbitration and audio

**Date:** 2026-11-17
**Phase:** `8.4`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-17
**Builds on:** Phase 8.1 — `cartridge::Cartridge`; Phase 8.2 — `cycles::MASTER_CYCLES_PER_68000_CYCLE`, `InstructionOutcome`, `InterruptScheduler::advance_master`, payload v4; Phase 8.3 — `vdp::Vdp` timing/line slots, `backend_api::media::{MediaSource, AudioChunk, VideoFrame}`, `MegadriveBackend::media_mut`, payload v5.

## Goal

Implement the Z80 subsystem, 68000/Z80/VDP bus arbitration, the YM2612 six-channel FM and PSG
audio, with a deterministic mixer/resampler and exact internal PCM hashes — so the commercial
ROM intros in 8.6 can produce video **and** audio.

## Approach

**Z80 core.** A new `z80/` module tree: `mod.rs` (register file, reset, step, snapshot),
`ops.rs` (main opcode table), `cb.rs` (shifts/rotates/bit ops), `ed.rs` (block moves/searches,
I/O, `IM`, `RRD`/`RLD`), `xy.rs` (`DD`/`FD` prefixes with `IX`/`IY` + displacement) and
`interrupts.rs` (IM 0/1/2 and NMI). The documented instruction set is implemented; `Z80::step`
returns `Z80Outcome { t_states: u32 }`, and one Z80 T-state is 15 master cycles (Z80 =
master/15). `StepOutcome` stays instruction-granular; the backend advances the master counter
accordingly and leaves a carry accumulator for VDP/68k slots.

**Z80 memory and I/O map.** The 68000 sees 8 KiB of Z80 RAM at `0x00A00000–0x00A01FFF` and the
Z80 sees `0x0000–0x1FFF` (mirrored to `0x3FFF`), the YM2612 at `0x4000–0x4003`, the bank
register write at `0x6000`, the PSG at `0x7F00–0x7F03` (`0x7F11` in the common addressing
idiom), and a 32 KiB banked ROM window at `0x8000–0xFFFF` selected by `0xA06000` (the Z80 bank
register). The Z80 cannot reach the VDP directly; that stays a 68000 responsibility and is
recorded in the capability page. The 68000-side YM2612 window is `0x00A04000–0x00A04003`.

**Bus arbitration.** `0xA11100` carries the Z80 bus request with hardware `ZBR` polarity:
**setting write bit 8 asserts the request, which stops the Z80 and gives the 68000 the Z80
window; clearing it returns the bus to the Z80.** Read bit 8 reports ownership: one while the
Z80 still has the bus and zero once it has yielded to the 68000, so a guest poll loop on
`0xA11100` terminates as on hardware. `0xA11200` controls the active-low Z80 reset (write
bit 8 = 0 asserts reset, 1 releases it). The model: the Z80 executes when no request is
asserted and the reset is released; while the Z80 owns the bus, a 68000 access to the Z80 window
is stalled by a fixed, documented number of master cycles (derived from the Z80 instruction
granularity) instead of returning an error. The yield is functional rather than
microcycle-exact — ownership is released on the request write instead of at the Z80 instruction
boundary — so a poll observes zero immediately; that limit is recorded. The 68000 access
stalls are deterministic and part of the state hash through the master counter. Z80 halt on a
68000 RAM access is the mirror rule.

**YM2612.** Six FM channels with four operators each, eight algorithms, feedback, envelope
generators (attack/decay/sustain/release with key scaling and rate scaling), LFO (AM/PM),
detune/multiple, the channel-6 DAC and the timer A/B counters/status flags. Register access is
the documented two-port address/data protocol on both the Z80 and 68000 windows. Timers set
status overflow flags in this phase; **interrupt delivery to the Z80** is phase 8.5. The
implemented register subset and any unmodelled bits are listed in the capability page.

**PSG.** The SN76489-compatible PSG: three square-wave tone channels and one noise channel
(15-bit LFSR, two rates), 16-level attenuation, per-channel frequency from a 10-bit divider.
It is write-only on hardware; reads return the documented open value and are tested.

**Mixer and resampler.** YM2612 and PSG run at their canonical rates derived from the master
clock (YM = master/7/144, PSG = master/15/16) and are mixed with integer arithmetic into
16-bit stereo. A documented rational resampler (integer phase accumulator, linear
interpolation, no floating point) produces the 48 kHz `AudioChunk` the media seam exposes.
PSG is panned centre; YM stereo follows the documented channel-6 DAC convention (both channels
equal in this phase) and that choice is recorded. Exact PCM hashes are pinned for synthetic
programs and must be identical across runs and — once 8.7 lands — across execution modes.
Because the pinned headless Exodus oracle has no audio output, cross-emulator audio evidence is
**device-state** equality (YM/PSG registers and channel state at synchronized boundaries),
never a sample diff; the limitation is stated in the evidence page.

**Porting fallback.** The project's default remains an independent Rust implementation from the
documented behaviour. If differential evidence shows a hand-written FM/PSG block cannot converge
within the phase, translating algorithms from the MIT-licensed non-headless Exodus source is
permitted **only** with a provenance entry, `THIRD_PARTY_NOTICES.md`/`LICENSE` update, owner
approval and a recorded line-by-line attribution. No **BizHawk** code may be used: `AGENTS.md`
records its heterogeneous licensing as non-reusable unless the owner explicitly authorizes a
separate legal review.

**State.** Backend payload `CFMD68K6` v6, state hash `CFMDSTATE6`, config hash `CFMDCONF6`:
adds Z80 state, arbitration latches, Z80 RAM, YM2612 state, PSG state and the mixer phase. v1–v5
rejected. `Capabilities::audio` becomes `true` when the phase's tests and evidence pass;
`rendering` stays `true` from 8.3.

## Tests

- Unit: Z80 documented opcodes across all prefixes, flags (`S/Z/H/PV/N/C`), `DAA`, block ops,
  `IM` modes, `EI` delay, T-state counts for sample instructions; YM envelope/operator/algorithm
  tests per channel; PSG tone/noise/attenuation; resampler phase and output length.
- Property: Z80 decode never panics; a random but bounded instruction stream leaves the register
  file in range; snapshot round-trip restores every Z80/YM/PSG field.
- Integration: a synthetic Z80 program writes YM registers and produces a deterministic PCM hash;
  a second identical run matches; arbitration request/release stalls deterministically; Z80 IRQ
  from the YM timer is delivered in 8.5, but the YM status flag is observable here; the 8.1 boot
  cartridge still boots and the 8.3 frame path still renders.
- Differential: YM2612/PSG state equality against the pinned oracle at synchronized boundaries,
  with a negative control; exact PCM hashes pinned on the ChronoFork side across runs.
- Regression: full gate; synthetic `demo` byte-identical; `megadrive demo` deterministic;
  v1–v5 snapshots rejected.

## Open Questions

None. Exact internal PCM hashing (not cross-emulator sample comparison), the 48 kHz output rate,
the timer-IRQ split to 8.5 and the Exodus-only porting fallback were decided with the owner on
2026-11-17.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Full Z80 + YM2612 is a very large phase | Phase overruns | Module split, per-block tests, ~15 tasks; timers split into 8.5 |
| FM accuracy diverges from real hardware | 8.6 intros sound wrong | Documented algorithms, oracle state comparison, envelope/operator unit tests, Exodus fallback with provenance |
| Resampler changes PCM bytes across edits | Broken hashes | One documented resampler, exact fixtures, cross-mode equality in 8.7 |
| Arbitration model stalls unrealistically | Compatibility | Deterministic fixed stall; documented functional model; 8.6 drives real games |
| Payload v6 break | Fixture invalidation | Reject-only versioning and supersession notes |
