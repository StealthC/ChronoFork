# Native Windowed Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an optional native window (winit + softbuffer + cpal) that presents video and audio, maps keyboard input to the controller, paces at 60/50 fps and supports pause/step/save/load, without changing the headless path.

**Architecture:** New `chronofork-frontend` crate depending only on core, backend-api and runtime; the CLI injects `Box<dyn Backend>`. ADR-0015 records the decision and supersedes ADR-0013's no-toolkit constraint for this crate only.

**Tech Stack:** Rust 2024, `winit`, `softbuffer`, `cpal`, `chronofork-runtime`, `chronofork-backend-api`.

**Spec:** `docs/superpowers/specs/2026-11-17-8.8-native-frontend-design.md`

## Global Constraints

- No `unsafe` in first-party code; dependency `unsafe` is allowed and documented in the ADR.
- No toolkit/audio dependency may enter core, backend-api, sessions, service, transport, gui or
  megadrive.
- The frontend never owns canonical state: frames/audio come from `MediaSource`, save/load through
  `Backend::snapshot`/`restore`.
- Headless builds and all existing tests must work with no display and no audio device.
- Pacing never changes canonical hashes; the runtime from ADR-0014 owns the clock.
- Every task ends with its own tests passing and a commit.

## Review Focus

- A missing audio device must degrade to silent video, never panic, hang or block the event loop.
- Pause must stop all stepping (no hidden catch-up), and step must advance exactly one frame.
- Save/load must reject a snapshot from a different backend/config without touching live state.
- Scaling must be deterministic and bounded; an oversized window must not allocate unchecked.
- Keyboard mapping must not stick keys after focus loss (release all on `Focused(false)`).
