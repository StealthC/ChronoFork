# Complete VDP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the complete VDP — CRAM/VSRAM, 256/320 rendering with planes/window/sprites/priority/shadow, DMA, FIFO timing, H/V counters and VBlank/HBlank interrupt control — and expose deterministic video frames through a backend-neutral media seam.

**Architecture:** `vdp.rs` splits into `vdp/{mod,regs,timing,render,dma,fifo}`. The device owns its state and snapshot (`CFVDP002` v2); the backend drives it from master cycles, adds FIFO/DMA wait cycles to instruction cost, and produces `VideoFrame`s through `backend-api`'s `MediaSource`. Payload moves to `CFMD68K5` v5.

**Tech Stack:** Rust 2024, `chronofork-core`, `chronofork-backend-api`, `chronofork-megadrive`, `chronofork-test-backend`, `chronofork-cli`.

**Spec:** `docs/superpowers/specs/2026-11-17-8.3-vdp-design.md`

## Global Constraints

- No `unsafe`, no new third-party dependency, no `unwrap()` in production code; typed errors.
- Rendering and DMA must be pure functions of canonical state and the master-cycle timeline; never
  read host time, environment or window size.
- Frames are deterministic: identical input sequence and start state produce byte-identical
  `VideoFrame`s and hashes.
- State/format changes are reject-only and versioned (`CFVDP002` v2, payload v5); older versions
  rejected.
- Interlace, dot-exact H counters and the physical byte-swapped VRAM layout remain documented
  limits; do not claim them.
- Every task ends with its own tests passing and a commit.

## Review Focus

- A byte write to the data port must not double-advance the auto-increment; byte reads select the
  correct lane of the 16-bit word.
- FIFO overflow must add exactly the documented wait cycles and never drop or reorder a write.
- Sprite collision/overflow status must latch and be observable through the status port, and a status
  read must not clear VBlank/HBlank pending unless the hardware does.
- VRAM writes must mask addresses to the 16-bit VRAM space (`0xFFFF`) and CRAM to 6-bit indices;
  out-of-range register writes are typed errors.
- DMA source/destination arithmetic must not read or write outside VRAM/CRAM/VSRAM; a truncated
  transfer must fail before mutating state.
