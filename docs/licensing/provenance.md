## External oracle use (no code incorporation)

Exodus headless (`exodus-for-ais`, branch `linux-headless`, commit
`ec0056151f3ff1c334d09ee375abb30a68fdfec5`) is used only as an **external
oracle** for differential instruction-trace evidence, in [EPIC-0002](../epics/EPIC-0002-megadrive-slice.md)
E2-12. The evidence is recorded in
[Oracle differential instruction-trace evidence](../research/oracle-differential-evidence.md).
The final post-repair run passes both synthetic ROMs; the earlier pre-repair FAIL
and its E2-13 core repair are preserved as history in that page and under ignored
`.research/evidence/before-repair/`.

- The oracle is built from a pinned commit in the ignored
  `.research/upstream/exodus-headless` checkout and invoked as separate
  `exodus-probe`/`exodus-mcpd` processes. Its trace dumps and MCP responses are data.
- No upstream source, headers, fixtures, binaries, ROMs or trace dumps were copied
  into tracked ChronoFork files or committed to the repository. Everything used for
  the evidence stays under ignored `.research/` paths and is not redistributed.
- The comparison harness (`scripts/oracle-diff.py`) and the synthetic differential
  ROMs are original ChronoFork work, written from the observed trace/state formats
  without copying upstream implementation.
- Because no upstream code or fixture was incorporated, `THIRD_PARTY_NOTICES.md`
  and `LICENSE` do not change as a result of this use. The upstream MIT notice and
  the open per-file copyright question above still apply to any future reuse,
  including embedding or vendoring oracle code.
- Pinned binary SHA-256 values identify the exact external artifacts used; rebuilding
  the same commit is expected to reproduce behaviour, not a bit-identical binary.
